# 2026-11-17 初次采集记录

这是验证采集流程的小样本，不是稳定的性能排名。Rust Harness 基于 `c0a34ed` 并加入本次计时代码，以 Windows 本地 debug 构建运行；模型为智谱 Coding Plan 的 GLM 5.3 Flash，Anthropic 协议、high effort、`never` 权限。各组交错运行 3 次，所有 24 次任务均退出成功并通过六个关键词检查。短任务和长会话是相同的三文件读取任务；长会话附加 30 轮合成历史，具体内容见示例配置。短任务与长会话的初始化计时范围不同，不能相互比较绝对耗时。

| 配置 | 短任务总耗时中位数 | 合成长会话总耗时中位数 |
|---|---:|---:|
| 三项均开启 | 11.38 秒 | 9.53 秒 |
| 关闭工具并发 | 12.01 秒 | 15.80 秒 |
| 关闭自动压缩 | 11.25 秒 | 11.36 秒 |
| 关闭 HTTP 连接复用 | 11.49 秒 | 22.66 秒 |

所有短任务均为 2 次模型请求和 3 次工具调用；长会话有 3 个样本增加到 3 次模型请求、4 次工具调用，因此总耗时差异不能归因于开关。长会话三项均开启时，模型请求耗时之和中位数约 9.38 秒，工具批次约 51 毫秒，历史读取约 2.08 毫秒，投影约 0.18 毫秒；阶段中位数分别计算，不能相加还原一次运行。所有样本均未触发自动压缩，不能评价该开关。模型服务波动、生成轨迹、少量样本、debug 构建和采集时有少量其他本地工作，都限制本次结果。建议使用 release 构建、更多样本、空闲机器及真实长会话重新测量。

上面的试采没有取得可比较的 ZCode CLI 样本。原始结果保存在运行机器的 `target/benchmark-comparison-results/` 和 `target/benchmark-long-results/`，不纳入 Git；其中包含任务输出，分享前应检查内容。

## 2026-11-18 官方桌面界面短任务对照

用户在两个桌面程序中分别新建三个会话，以同一条 51 字符提示词读取同一份三文件 fixture；每次答案均包含六个预期字段。ZCode 安装版为 3.18.2（可执行文件版本 3.18.2.10443），Rust Harness 安装版为 0.1.6；二进制 SHA-256 分别为 `e853398ea2023e3e472fd2799389ad02445df5c2bfd36b2ed1f1e3dfe3dc958e` 和 `453013892c0606b00e89452c872268ea341be4b737c1c1b57842af4b806ab724`，不能由版本号推断其具体 Git 提交。CPU 为 i5-13600KF。两边各次均为两次主模型请求和三次读取；模型为 GLM 5.3 Flash、high 档位、智谱 Coding Plan Anthropic 协议。ZCode 的数据库记录了模型和档位；Harness 根据用户设置及测试后的默认设置确认。ZCode 使用 yolo 模式直接读取原目录，Harness 使用 auto 模式和隔离副本，隔离及权限语义不能保证完全一致。

| 程序 | 第一次 | 第二次 | 第三次 | 中位数 |
|---|---:|---:|---:|---:|
| ZCode 3.18.2 GUI | 5.962 秒 | 21.731 秒 | 8.206 秒 | 8.206 秒 |
| Rust Harness 0.1.6 GUI | 12.312 秒 | 11.555 秒 | 10.916 秒 | 11.555 秒 |

计时分别取 ZCode `turn_usage.duration_ms` 与 Harness 持久化事件 `turn.start` 到 `turn.end` 的差值；两者是运行时回合时间，并非严格的点击到屏幕渲染完成时间，且口径可能有细微差异。工作区打开和首次复制发生在计时之前，未测量其耗时。先完成三次 ZCode，再完成三次 Harness，并非交错顺序；网络和服务负载可能变化。ZCode 的第二次回合中，一次主模型请求耗时 18.156 秒；它的会话标题生成也使用模型，但不属于主回合，未计入上表。三次的波动和样本数量都不足以证明稳定的速度差异。

上下文与缓存条件并不相同：ZCode 两次主请求的总输入各约 2.8 万 token，缓存读取约 1.58 万至 2.78 万；Harness 各次约 4204 和 4311–4328 个输入 token，缓存读取均为 0。ZCode 的每个测试会话另外持久化了 9 条标记为 synthetic 的 user 消息，尚未区分其中的工具结果和其他内部消息。上述数字来自各自运行记录，ZCode 的输入量已包含缓存读取部分；它们说明两边请求负载和缓存状态不同，不能把总耗时差归因于调度或连接复用。未在官方 GUI 中进行等价长会话或工作区模式对照，也没有记录 GUI 的可见渲染耗时。
