## 验收范围

- 真实 Windows 上完成“读取项目 → 修改托管副本 → 运行验证 → 人工审阅差异并同步 → 重启继续会话”，原项目在确认前不变。
- DeepSeek、智谱 Coding Plan 两个供应商分别支持三协议；共享凭据服务，只读取已配置凭据，不导出或记录密钥。真实调用只针对合成项目，限制请求数、输出预算和总时长。
- 文件读写、Shell 的统一审批、拒绝、取消、历史和异常结算；工作区指令及技能可被模型读取。
- 会话附件导入、模型按会话读取、完整工具输出访问与下载；跨会话访问拒绝。
- WASM 工具、上下文及工具钩子、受控文件/HTTP/KV；声明式设置、命令、主题和文本/表格/文件卡片。生命周期与钩子不能在工具审批前取得文件写入或网络副作用权限。
- MCP 工具和资源通过宿主权限、审批、日志流水线执行；本地 HTTP/stdio fixture 验证。
- 中文桌面输入、发送、审批、同步、重连、托盘和重启；单一 NSIS 包使用系统已有 WebView2，保留管理员安装与 UAC 清单。

## 补齐约束

附件仅保存内容哈希和会话引用，模型上下文不包含宿主附件路径。文本采用 UTF-8 边界分块，二进制使用 base64；导入限制 20MiB，每次读取最多 32KiB。大工具输出在事件中保留完整对象引用，不能只留下无法访问的预览。

插件界面由宿主渲染。设置根据清单声明的基本类型及范围验证；命令绑定会话，批准后执行，取消/停用需释放审批及活动状态。主题仅允许白名单变量和值，关闭设置面板后仍对当前工作区生效；停用或切换工作区移除其效果。结果卡片不执行插件 HTML 或脚本，文件预览只能访问工作副本并限制读取体积。

显式卸载清理仅操作 Windows KnownFolder 下的 RustHarness 及 dev.rustharness.desktop 应用目录。拒绝根重解析路径、运行中的宿主锁；暂存完成前失败须尝试回滚。RustHarness 的 host.lock 在暂存及删除旧数据期间保持持锁，Windows 不支持持有子文件句柄时重命名整个根，因此暂存其余一级条目。仅安全删除暂存内容，最后删除空根；不递归清理并发新建内容。默认卸载保留数据。安装器不扫描项目、自定义数据目录或修改原项目 ACL。

## 验证方法与完成门槛

| 项目 | 证据 |
|---|---|
| Rust、协议、存储、平台、扩展 | 完整 workspace 测试、Clippy、格式检查；本地 HTTP/SSE 与真实组件 fixture |
| 桌面界面与 SDK | 前端交互测试、生产构建、类型绑定、TypeScript/Python SDK 检查 |
| 真实供应商 | 两供应商六条实际生成请求；工具链路另行记录，不能以连接测试替代 |
| 原生桌面与安装 | 隔离 Windows guest 中实际安装、覆盖升级、输入/工具审批/同步/重启、默认卸载与显式清理；保留截图和 JSON 结果 |
| 安装权限 | 安装器及应用 PE 清单核验；管理员 Sandbox 验证不能冒充标准用户 UAC 安全桌面交互 |
| 文档 | 状态与证据一致、本地 Markdown 链接和 git diff --check 通过 |

所有验收输出使用合成数据并保存在仓库 .cache 下，不提交用户凭据、会话或宿主数据。主机正在运行的用户应用不作为自动安装或清理目标。缺少环境或失败时明确记录，不将未执行项标记通过。

PTY、SSH、LSP、市场、自动更新公开签名和其他 P2/P3 能力不计入本次完成门槛。单安装包策略取代历史双包要求，历史交付记录保留对应版本含义。
