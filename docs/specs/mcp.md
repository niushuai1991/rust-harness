## 目标与阶段

第一阶段支持保存和管理服务器配置、Windows 下本地 stdio 与 Streamable HTTP、工具发现与调用、状态和错误反馈，并覆盖桌面与 CLI。第二阶段单独交付 OAuth、动态工具目录、资源模板和 ACP 服务器配置。工具目录缓存、延迟启动、MCP Apps、服务端交互和本系统作为 MCP 服务器不属于第一阶段。

现有适配器基于 rmcp 3.8.0；实施时先验证 SDK 支持的协议版本和能力，只有存在测试证明的缺口才升级。第一阶段不承诺支持未验证的协议版本或功能。

## 配置、身份与信任

- 配置由宿主的数据目录管理并持久化，使用现有 SQLite settings 存储保存非秘密字段。全局配置和项目配置分开存放，同名时项目配置整项覆盖全局配置；无项目会话只读取全局配置。桌面、CLI、自动化和运行时共用解析结果。
- 每个配置包含服务器标识、启用状态、传输类型、启动和调用超时以及允许/禁止的工具。缺省启动超时 30 秒、调用超时 60 秒，取值范围均为 1 至 3600 秒；显式允许列表先过滤，再应用禁止列表。
- stdio 配置包含可执行文件、参数、可选工作目录及环境变量；HTTP 配置包含 URL 和请求头。保密值只能引用环境变量名或系统凭据引用，不能以明文保存到项目文件、普通设置、事件、日志或模型上下文。缺失引用时明确报错，不向服务器发送空凭据。
- 用户在设置中新增和修改全局配置是显式配置行为；项目来源配置在启用前必须获得用户对实际命令、参数、目录、环境变量名或 HTTP 地址及请求头名的确认。配置的安全相关字段改变时，先撤销旧信任再要求确认；拒绝、取消或无人值守都不能视为授权。无交互入口不能启动未信任项目配置。
- 服务器身份是配置来源作用域和服务器标识的组合；活动连接还绑定有效执行根及认证身份。模型可见名称由内部映射表解析为完整身份，不能靠前缀匹配授权。命名冲突必须稳定消解且不能影响内置工具。
- 每个会话只看到自己有效配置与连接提供的工具；跨项目、跨执行根和跨凭据的服务器不能误复用。子代理继承父会话的作用域与有效执行根。执行工具、读取资源和断开连接时重新校验调用者的完整身份及当前连接代。
- 配置变更、停用和删除使旧连接不可接受新调用，释放旧资源并结算在途请求；新连接成功前不得将旧连接伪装成新配置。变更与连接启动并发时，旧启动结果不得覆盖新配置。

## 本地进程与执行位置

- 本地 stdio 是长期运行进程，由宿主按当前会话解析出的执行位置启动；配置和授权展示实际程序、参数、工作目录及执行模式。服务器标准输出只用于协议，标准错误有界采集并脱敏后作为诊断信息。
- 直接模式的执行根为源项目目录：服务器以宿主令牌运行，用户在启用服务器前明确获知其可访问宿主环境。确认服务器连接不改变现行五档工具审批策略。
- 副本、worktree 和无项目 scratch 使用其现有执行根与能力标识，通过受限令牌和受控目录授权启动；禁止失败后静默以宿主权限重试。非交互情况下需要确认而未获确认时不启动。
- 配置工作目录只能为执行根或执行根内的目录；路径规范化后再次校验，拒绝符号链接或路径跳转导致的越界。进程获取的环境变量按配置明确提供，不输出其值。
- Windows 使用 Job Object 管理进程树。握手失败、断开、替换、会话关闭和宿主退出应关闭管道并回收进程；失败须可见，不能误报已断开且清理成功。
- 增加多个空闲服务器同时存在的 Windows 回归测试，验证文件操作不会被空闲管道阻塞；如当前实现不满足，再使用可异步等待的命名管道并限制访问。

上述能力的实际实现与验证情况以能力状态矩阵为准。

## HTTP、工具与审批

- 第一阶段支持 Streamable HTTP。地址只允许 HTTP 或 HTTPS，不接受 URL 内嵌用户名和密码；远程服务器不受本地 Windows 沙箱约束。
- 启动、工具发现和调用分别受配置的超时限制；服务器失败不阻断其他服务器或普通对话。状态至少包含未连接、连接中、可用、失败和已禁用，界面展示不含秘密的错误原因。
- 会话开始时并发启动已启用且已信任的服务器（最多四个）；失败记录状态，不自动重放工具调用。仅把当前作用域已启用、已信任且已连接的服务器工具暴露给模型；调用前再检查作用域、连接代、工具白名单和参数 schema。MCP 工具沿用现有需审批工具处理及五档审批策略。计划模式不暴露也不执行 MCP 工具。
- 工具调用取消、超时或连接中断时返回清晰失败；已经发出的请求可能有副作用，结果未知时不自动重放。事件流仍要结算失败调用。
- 工具返回保留错误标记与结构化结果；模型侧优先使用可见内容，只有没有可见内容时回退结构化内容，避免重复。图片按现有多模态能力处理；不支持时返回说明。结果和诊断设大小上限，超限时明确告知截断。
- 连接恢复和自动刷新工具目录属于第二阶段；第一阶段断连后须明确显示状态，可由用户重新连接。连接成功时重新发现工具。

## 用户入口

- 桌面 MCP 面板支持新建、编辑、启用、禁用、删除、连接、断开和查看配置来源、工具及状态；需要信任时显示完整的安全相关配置。
- CLI 提供对应管理和状态操作；与桌面共用配置和权限逻辑。无交互环境不代替用户确认信任。
- 现有手动连接入口迁移到统一服务；旧接口若继续提供，行为与作用域校验必须一致。

## 验收

- 配置重启保留；项目覆盖全局；无项目只用全局；不同项目同名服务器及不同执行根互不串用；项目配置修改撤销信任。
- direct、replica、worktree、scratch 及子代理使用正确执行根与权限；Windows 进程异常、握手失败、取消、断开及应用退出均覆盖进程树清理。
- 审批策略和计划模式边界有效；不确定结果的工具调用不重放；失败结算持久化。
- 验证文本、结构化、图片、错误及超大响应；环境变量和令牌不会泄露到设置、日志或模型输入。
- 使用受控 stdio 和 HTTP 服务器完成端到端测试，并记录协议版本；第三方服务器未实际验证时必须注明。
- 代码实现按仓库 TDD 流程，并完成 Rust、前端和相关端到端检查。
