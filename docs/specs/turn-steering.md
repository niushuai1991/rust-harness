# 运行中插话

- 日期：2026-11-22（计划批准）
- 状态：实施中；交付与验证以能力状态矩阵为准。
- 范围：桌面端向同一会话当前运行回合提交额外用户输入，运行时持久化和按模型请求边界处理；CLI、ACP、JSON-RPC 新入口不在本期。

## 交互与处理

桌面会话运行时，输入框发送普通消息作为当前回合插话；停止按钮独立保留。客户端携带当前 `runId` 和消息标识，不存在运行回合或回合已变更时返回错误，保留输入，不能悄然改作下一回合。发送成功表示持久化受理，并非模型已经读到；界面显示等待当前步骤完成，随后显示已纳入上下文或未处理。多条输入按受理顺序处理。

当前模型请求正常结束，已提交的工具批次结算后才处理插话，不取消已启动工具，不撤销副作用；审批等待不受影响。`ask_user` 待答复时，无附件和引用的普通文本仍作为文本答复；带附件或引用沿用排队语义。原模型、权限、执行位置和 token 预算保持不变；达到预算限制时不额外请求模型。插话的大小、附件、引用和技能提及沿用普通消息校验与上下文转换。

## 事件与并发

- `steer.queued {id,runId,content,attachments,quotes}`：输入经校验后持久化受理。
- `user.message {steerId,runId,content,attachments,quotes}` 和 `steer.applied {id,runId}`：同一事务写入，表示已纳入对话历史；广播在提交后进行。
- `steer.failed {id,runId,reason}`：受理后未纳入上下文，保留输入供用户手动重发。
- 同会话同消息 ID 与同内容的重复提交幂等，不同内容冲突；接收、最终队列检查及回合关闭必须串行化，受理的消息必有应用或失败结算。
- 取消、错误、预算耗尽或崩溃恢复时，将未应用消息标记未处理，不自动执行；恢复须幂等。已应用消息继续作为历史，不重放副作用。

运行时接口为 `Runtime::steer_session(session_id: &str, expected_run_id: &str, message_id: &str, text: String, attachments: Vec<String>, quotes: Vec<String>) -> AppResult<()>`。受理成功返回空结果；回合已关闭、标识不匹配、重复 ID 的内容冲突、校验或持久化失败均返回错误。幂等重试不追加重复事件。

## 展示和验收

时间线按事件顺序呈现插话和状态，分页返回回合 runId，插话受理事件可携带截至页面快照的结算状态；后台会话通过桌面持久事件通知更新。跨插话分段的工具调用与结果仍须配对。兼容旧事件、跨页回合及复制范围；原用户消息不能被挪到不对应的位置。测试覆盖发送与结束竞争、重复提交、事务失败、崩溃恢复、多个插话的模型输入顺序、工具/审批/提问边界、预算、取消、附件引用和技能、切换会话与跨页回放。具体能力和真实验收状态记录于能力状态矩阵。
