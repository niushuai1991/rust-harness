# 会话计划模式

- 日期：2026-11-13（计划拟制）
- 状态：设计规范；实现和验证情况见[能力状态矩阵](../capability-matrix.md)。
- 范围：会话计划模式、计划审阅与执行衔接，以及桌面计划和目标抽屉。

## 目标与边界

计划模式按会话生效，与权限模式独立。进入后以只读探索和方案制订为目标，禁止会话发起不安全的副作用；常规权限档位不能放宽该限制。模型可读取、搜索、提问并记录计划；工具与扩展不能仅凭名称或免审批标识推定安全。切换模式要处理在途执行和后台工作，不能证明安全时拒绝进入或继续执行，并明确告知用户。

## shell 只读放行

计划模式默认拒绝 shell，但调查需要 git 历史、文本搜索等只读命令，因此对内置 `shell` 工具按命令内容放行（2026-11-14）：

- 判定基于正向白名单（`harness-contracts` 的 `read_only_shell_command`），与审批免检和危险命令黑名单（`dangerous_shell_rule`）相互独立：无法静态证明只读（动态展开、重定向落盘、未知程序）一律拒绝。
- 引号感知分段后每一段都必须通过；仅放行纯只读命令——git 查询子命令、受限参数的 branch/tag/remote/stash/worktree/reflog/config、文件列表与读取、搜索、系统信息，以及任意程序仅带 `--version/--help/-V/-h//?` 的查询。构建、安装、测试类命令不放行。
- 重定向落盘拒绝（仅 `2>&1` 例外）；提权请求（`escalate:true`）一律拒绝；命令在沙箱内单次执行，失败按普通失败呈现，不触发提权重跑审批。
- 放行的只读 shell 不走审批通道，其余拒绝行为不变。

## 交互

- 桌面输入框的 `+` 菜单「计划」以及 `/plan` 是进入计划模式的入口，而非仅插入提示词。界面应明确显示当前状态并提供退出方式。
- 支持带任务的 `/plan`：成功进入模式后提交任务；切换失败时不应发送任务。CLI 与桌面应保持模式语义一致。
- 计划形成后，用户可以审阅、批准或提出修改意见。只有明确的用户确认才能转入执行；拒绝、取消、超时或无人值守均不能视为批准。批准后的执行应能看到被批准的计划。
- 计划、目标和待办仍以事件流为事实来源。桌面只读总览迁到右侧抽屉，可查看历史并跳转会话，不提供直接修改通道。

## 状态与验证

模式切换与回合执行需要协调并发，重启或恢复会话后不能意外失去只读保护。验证应覆盖：权限自动放行时的拦截、写操作及扩展入口、历史后台工作、重启恢复、批准/拒绝/无人在场、切换会话和抽屉交互；shell 只读放行还应覆盖只读命令免审批放行、写命令与重定向拒绝、提权请求拒绝、沙箱拒绝不触发提权重跑。
