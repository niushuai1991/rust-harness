# 双供应商、多协议接入实现记录

依据：2026-11-04 用户批准的双供应商、多协议接入计划。

目标：DeepSeek 与智谱 Coding Plan 两个内置供应商，每个内部选择 Chat Completions、Responses 或 Anthropic。内置名称和端点不可修改，自定义供应商独立管理，不复制密钥。

交付任务：
- [x] 供应商目录、共享配置服务、SQLite v1→v2 备份迁移、桌面与 CLI 接口。
- [x] 统一消息、三协议编码和流式解析、协议回放、请求路由快照。
- [x] 双供应商设置界面、自定义供应商和模型管理及交互测试。
- [x] 集成回归、类型生成、版本 0.1.2、标准和离线安装包及 UAC 验证。

接口约定：`ApiMode` 使用 `chatCompletions`、`responses`、`anthropic`；供应商持有多个协议端点，用户配置持有凭据引用和代理，模型引用供应商、协议与模型 ID。旧模型逐项迁移为自定义供应商，不按地址合并。

Ruling: 在现有专用功能分支 feat/rust-harness 上工作，保留用户当前工作位置；不创建额外检出。
Ruling: 配置、协议和前端按文件所有权并行实施，最后统一回归；避免重复修改共享入口。
Ruling: 保留 ModelConfig 旧的有效地址等输出字段以兼容 SDK，运行时仅以供应商服务解析的配置发起请求。

验证：供应商六条路由、本地 SSE 模拟完整 Agent 工具循环、流式错误与取消、私有历史隔离和重启回放、迁移备份与版本守卫、前端交互、Rust 测试/Clippy/fmt、类型与构建、两个 NSIS 包权限清单。

审查补充：使用显式供应商 compatibility profile，复制保留该属性；接口按标准简单输入消息回放跨协议正文，Anthropic 需要关闭全部内容块后才能成功结算。

最终证据：75 Rust / 23 UI / 2 Python SDK；TypeScript SDK类型检查、Clippy、fmt与生产构建成功；两个0.1.2 NSIS及应用权限清单、桌面启动和单实例通过。详见[交付记录](delivery.md)。
